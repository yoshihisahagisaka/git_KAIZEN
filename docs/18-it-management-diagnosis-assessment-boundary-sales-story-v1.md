# 無料 IT経営診断 × IT経営KAIZEN 設計Assessment 境界・営業ストーリー v1.0

Status: **CANONICAL — SERVICE / SALES STORY**

この文書は、無料 IT経営診断と有料の IT経営KAIZEN 設計Assessment の価値境界、および営業説明で使用する基本ストーリーを記録する。

## 1. 基本原則

無料診断では、顧客のアンケート回答・経営者ヒアリングという情報は存在する。しかし、Evidenceによる確認が十分ではないため、企業の実態を確定FACTとして断定しない。

> **無料診断は、Futureに対して「どこにGapがありそうか」という可能性を発見する。**

有料Assessmentでは、台帳・管理表・手順書・規程・システム情報・契約情報等のEvidenceを確認し、FACT / UNKNOWNを形成する。

> **IT経営KAIZEN 設計Assessmentは、Evidenceに基づいて現在地を捉え、実際のGapとKAIZENを設計する。**

## 2. 無料診断とAssessmentの違い

| 項目 | 無料 IT経営診断 | IT経営KAIZEN 設計Assessment |
|---|---|---|
| 主な情報源 | アンケート・経営者ヒアリング | Evidence、既存資料、管理情報、必要な追加確認 |
| 情報の扱い | Observation / 自己申告 / ヒアリング内容 | FACT / UNKNOWN / Evidence |
| 現在地 | 可能性を示す | 事実に基づいて整理する |
| GAP | GAPの可能性 | FACTに基づくGAP |
| Root Cause | 仮説 | Evidenceを踏まえて確認・整理 |
| KAIZEN | 改善の方向性 | 実行可能な改善設計 |
| 1年後 | 詳細設計しない | FACTと採用する改善に基づく「期待する状態」 |
| 主目的 | 気づきをつくる / 確認すべきことを明らかにする | 経営判断できる状態をつくる |

## 3. 営業上の重要な価値境界

有料Assessmentを「無料診断の詳しい版」として説明しない。

価値の違いは情報量ではなく、**確からしさと経営判断可能性**にある。

### 無料診断

> **可能性を発見する。**

### 設計Assessment

> **可能性で会社を変えない。事実を確認してから、何を変えるかを決める。**

この考え方を営業ストーリー、提案資料、LP、診断レポート、トークスクリプトへ共通して使用できる。

## 4. 無料診断で使用する表現

無料診断では、Evidence未確認の内容を断定しない。

推奨表現：

- 「御社には、このようなGapが存在する可能性があります」
- 「ヒアリング内容から、この部分は詳しく確認する価値があると考えられます」
- 「現時点では確認できていません」
- 「この状態になっている可能性があります」
- 「AssessmentでEvidenceを確認することで、実態を明らかにできます」

避ける表現：

- 「御社は管理できていません」
- 「御社の成熟度は○点です」
- 「この施策で○％改善します」
- Evidenceなしで事実・原因・効果を確定する表現

## 5. Assessmentで提供する価値

Assessmentでは、必要なEvidenceを確認し、FACTACT上に現在地を形成する。

> **Future → FACT / UNKNOWN → GAP → ROOT CAUSE → KAIZEN → DECISION → ACT**

Assessmentの価値はUNKNOWNをゼロにすることではない。

> **経営判断や実行に必要なFACTを確認し、重要でないUNKNOWNはUNKNOWNのまま残してよい。**

## 6. サービス全体のストーリー

> **無料診断：可能性を発見する**
>
> ↓
>
> **設計Assessment：FACTで現在地をつくる**
>
> ↓
>
> **実行：KAIZENする**
>
> ↓
>
> **FACTACT：CHANGE / NEW FACTを蓄積する**
>
> ↓
>
> **本当に会社が変わったか確認する**
>
> ↓
>
> **NEXT KAIZEN**

別表現：

> **仮説 → FACT → ACT → CHANGE → NEW FACT → NEXT KAIZEN**

## 7. 営業トークの基本骨格

営業担当者は、無料診断後にいきなり商品を売るのではなく、次の順序で説明する。

1. 経営者が実現したいFutureを再確認する
2. 無料診断で見えた「可能性」を説明する
3. 現時点で確認できていない事項を明示する
4. なぜEvidence確認が必要なのかを説明する
5. 「可能性で会社を変えない」というFACT FIRSTの考え方を説明する
6. IT経営KAIZEN 設計Assessmentを、事実に基づく経営判断のためのサービスとして提示する

## 8. 営業トーク例

> 今回の無料診断では、経営者様へのアンケートとヒアリングをもとに、御社が目指す未来に対して、現在どこにGapがある可能性があるのかを整理しました。
>
> ただ、私たちはヒアリングだけで「御社はこういう状態です」とは断定しません。実際の管理表や手順書、システムの情報を確認していないからです。
>
> 可能性だけでシステムを導入したり、業務を変えたりすると、本当の原因と違うところへ投資してしまうことがあります。
>
> そこで次の「IT経営KAIZEN 設計Assessment」では、必要なEvidenceを確認し、何が事実として分かっていて、何がまだ分からないのかを整理します。そのうえで、御社が目指す未来とのGapと、何を変えるべきかを設計します。
>
> **可能性で会社を変えない。事実を確認してから、何を変えるかを決める。** これがIT経営KAIZENの考え方です。
