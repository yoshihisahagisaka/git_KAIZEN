# IT経営KAIZEN — First Customer Sales Execution Playbook v1

Status: **BUSINESS EXECUTION / LAUNCH VALIDATION**  
Date: 2026-09-13

## 1. Purpose

IT経営KAIZENを既存顧客・既存接点へ実際に提案し、

> **Management Conversation → Free Diagnosis → Management Feedback → Assessment Proposal → Decision**

までを再現可能にする。

営業の目的は「Managed Serviceへ誘導すること」ではない。

> **顧客がFUTUREを言語化し、FACT / UNKNOWNを分け、次に必要なDecisionへ進めること。**

---

## 2. Official Brand Language

Corporate Philosophy:
> **ITで、企業に自由を。人々に未来をつくる。**

Corporate Slogan:
> **ITを企業成長の武器にする**

IT経営KAIZEN:
> **経営者が実現したい会社のFUTUREから逆算し、ITを使って企業を継続的に良くしていくコンサルティング事業。**

---

## 3. First Account Selection

初期検証では大量Cold Outreachより、既存の信頼・情報があるAccountを優先する。

### Priority A
- 既存顧客
- 経営者 / 役員 / 管理本部長へ接点を作れる
- Growth / IPO / Security / IT leader change等のTriggerがある
- IT環境や運用の一部をatLIBが既に知っている

### Priority B
- 100〜500名程度 — HYPOTHESIS
- SaaS / Device / Account / Vendorが増加
- 少人数IT体制
- 改善意思がある

### Do not exclude solely by size
Complexity / Trigger / Future / Capability gapを優先する。

## 4. Pre-contact Account Brief

営業担当は接触前に以下だけ整理する。分からないものはUNKNOWN。

| Item | Status / Value |
|---|---|
| Employees | FACT / UNKNOWN |
| Business / growth context | FACT / UNKNOWN |
| Known IT structure | FACT / UNKNOWN |
| atLIB current relationship | FACT |
| Known Trigger | FACT / HYPOTHESIS / UNKNOWN |
| Decision-maker candidate | FACT / UNKNOWN |
| Why now? | HYPOTHESIS until confirmed |
| Existing vendor | FACT / UNKNOWN |
| Potential Future theme | HYPOTHESIS |

Do not build a hidden diagnosis before speaking to customer.

## 5. Outreach Objective

Outreach CTAは「Assessmentを買ってください」ではない。

> **経営 / 管理側を交え、今後1〜3年の会社とITについて30分話す。**

### Existing Customer Outreach — PROPOSAL

「これまでITの一部をご支援する中で、個別業務だけでなく、会社全体としてITをどう活かすかをご相談いただく機会が増えています。

atLIBでは『ITを企業成長の武器にする』という考えのもと、経営が目指す未来から逆算してIT・運用・管理を見直す『IT経営KAIZEN』を始めています。

特定製品やベンダー変更を前提にせず、まず今後1〜3年で会社をどう良くしていきたいか、その未来に今のITが追いついているかを一度整理できればと思っています。

30分ほど、経営・管理側の方も交えてお話しする機会をいただけないでしょうか。」

---

## 6. First Meeting — 30 Minutes

### Phase 1 — 0–5 min: Why this conversation

「今日は製品やアウトソーシングのご提案から入るのではなく、まず御社がこれからどんな会社を目指しているのか、その実現にITをどう使えるかというところから伺いたいと思っています。」

### Phase 2 — 5–12 min: FUTURE

Ask:
- 1〜3年で会社をどう良くしたいか
- 成長 / 生産性 / Security / Governance / DX等の優先テーマ
- 組織 / 拠点 / Group / IPO / M&A等の変化
- ITに期待していること

Record:
- Customer wording
- Decision-maker wording
- Do not paraphrase into FACT beyond what was said

### Phase 3 — 12–20 min: Current FACT / UNKNOWN

Ask:
- IT体制
- Major platforms
- Identity / Device / SaaS
- Vendors
- Security / Governance
- IT management visibility
- recurring Work

Classify live:
- FACT
- UNKNOWN
- OBSERVATION if appropriate
- HYPOTHESIS only when explicitly labeled

### Phase 4 — 20–25 min: GAP / Work

Ask:
- IT担当者が何に時間を使うか
- 本来進めたいが進まないこと
- Duplicate management / spreadsheet update
- inquiry / joiner / leaver / account / device / vendor coordination
- system introduced but work not reduced

Do not diagnose root cause without evidence.

### Phase 5 — 25–30 min: Next step

If fit exists:

「今日のお話から改善できる可能性はいくつかありそうですが、まだ確認できていないこともあります。まず無料IT経営診断で、目指す未来、分かっている事実、まだ分からないこと、次に確認すべきことを整理してお返しするところから始められます。」

---

## 7. Meeting Exit Criteria

商談後にHumanが以下を記録する。

### FACT
Customer-confirmed facts only.

### UNKNOWN
Material items not confirmed.

### HYPOTHESIS
Potential gaps / root causes / improvement opportunities.

### FUTURE
Customer's intended future in their own language.

### Next Decision
Choose:
- Free Diagnosis
- Direct Focused Project exploration
- Nurture
- No Fit now

Assessmentはこの時点で必ず売らない。

---

## 8. Free Diagnosis Execution

Purpose:
> **可能性と、次に確認すべきことを発見する。**

### Inputs
- initial conversation
- questionnaire
- customer-provided known facts
- existing atLIB facts where valid for current context

Known historical FACTを今回へ自動適用しない。

### Output — 5 blocks
1. FUTURE
2. FACT / UNKNOWN
3. GAP
4. WHY — hypothesis / confirmation needed
5. NEXT DECISION

### Diagnosis Rule
No maturity score.
No invented percentage improvement.
No vendor replacement conclusion.
No atLIB execution conclusion.

---

## 9. Management Feedback Meeting — 45 Minutes Candidate

### 0–5 min — Reconfirm FUTURE

「前回、今後の会社像として○○というお話がありました。まずここに認識違いがないか確認させてください。」

Customer confirms / corrects.

### 5–15 min — FACT / UNKNOWN

Show two columns:
- confirmed
- not yet confirmed

Key effect:
> **分からないことが見えること自体を価値にする。**

### 15–25 min — GAP

Show:
- Future requirement
- Current known state
- Gap

Avoid maturity score.

### 25–32 min — WHY / KAIZEN possibility

Show HYPOTHESIS explicitly.

Use 6 Lenses:
- なくす
- 自動化する
- 標準化する
- 任せる
- 残す
- 整える

Do not decide Actor yet.

### 32–40 min — Next Decision

Classify each theme:
- enough FACT to decide
- evidence needed
- direct Project possible
- Assessment recommended
- defer

### 40–45 min — Assessment Proposal if needed

Only when material Decision requires deeper Evidence.

---

## 10. Assessment Transition Logic

Do not say:
> 「無料診断の次の商品がAssessmentです。」

Say:
> **「ここから先は、可能性のまま投資判断せず、Evidenceを確認して現在地と次の一手を確定する必要があります。」**

Then:

> **「そのための工程がIT経営KAIZENの設計Assessmentです。」**

This keeps Assessment inside the IT経営KAIZEN process rather than presenting it as an unrelated service.

---

## 11. Assessment Proposal — Value Before Price

Sequence:

1. FUTURE
2. Material Decision to be made
3. Current UNKNOWN / insufficient Evidence
4. Risk of deciding from assumptions
5. Assessment activities
6. Decision outputs
7. Schedule / scope
8. Price

Price is shown only after value / scope explanation.

### Price — DECIDED

> **¥1,200,000 pre-tax**

Do not put price on broad awareness / initial IT経営KAIZEN overview by default.

---

## 12. Assessment Close

Candidate:

「無料診断で改善可能性は見えてきました。ただ、ここで製品導入や外注を決めると、まだ仮説で会社を変えることになります。

設計Assessmentでは、必要なEvidenceを確認し、御社が目指す未来に対して現在どこにいるのか、何を変えるべきか、どの順番で進めるべきかを経営判断できる状態まで作ります。

そのうえで、実行を御社自身で行うのか、今のベンダーに依頼するのか、別の専門会社に依頼するのか、atLIBが担うのかを決めます。」

---

## 13. Assessment Objection Capture

Do not only record Win / Lost.

For every proposal record:
- price objection
- timing objection
- perceived value gap
- scope concern
- internal approval issue
- existing vendor concern
- trust / evidence concern
- free diagnosis was sufficient
- direct project preferred
- other

Capture customer wording where possible.

---

## 14. Post-Assessment Decision Meeting

Assessment final meeting is not an upsell meeting.

Order:

1. FUTURE
2. FACT / Evidence
3. GAP / ROOT CAUSE
4. Required IT Capability
5. KAIZEN Options
6. Human Decision
7. 1-year CHANGE / KGI / KPI
8. Actor Allocation
9. ACT options

Only after Actor Decision:
- atLIB Project proposal
- atLIB Managed Capability commercial design

if atLIB selected.

## 18. Go / Adjust Questions After Initial Cases

Do not ask only "Did it sell?"

Ask:

1. Did executives understand IT経営KAIZEN as one continuous process?
2. Did they confuse it with BPO / MSP / staffing?
3. Did FUTURE-first conversation create a better discussion?
4. Did Free Diagnosis create meaningful Next Decision?
5. Was the Assessment boundary understood?
6. Was ¥1.2m rejected because of price or because value was unclear?
7. Which customer characteristics correlated with interest?
8. Which Work patterns indicate FACTACT leverage?
9. Which cases should not proceed to Managed Capability?
10. What FACT requires a Business Model revision?

## 20. Guardrails

> **FUTUREから始める。**

> **FACTとUNKNOWNを分ける。**

> **無料診断で分かったふりをしない。**

> **Assessmentを別商品として押し込まない。IT経営KAIZENのDecision工程として説明する。**

> **価格より先に、Decision Valueを説明する。**

> **atLIBに発注することがゴールではない。会社が良くなることがゴールである。**

> **顧客の反応もFACTとして次のKAIZENへつなげる。**
