# IT経営KAIZEN — Launch Sales Kit v1

Status: **BUSINESS EXECUTION ASSET / SALES VALIDATION**  
Date: 2026-09-13

## 1. Purpose

IT経営KAIZENを実商談で検証・販売開始するための営業共通Kit。

このKitは営業担当者がBPO、製品、技術テーマから商談を始めることを防ぎ、Canonicalの以下を実行する。

> **FUTURE → FACT / UNKNOWN → GAP → ROOT CAUSE → KAIZEN → HUMAN DECISION → ACT → CHANGE → NEW FACT**

Primary Commercial Conversion：

> **無料IT経営診断 → IT経営KAIZEN 設計Assessment ¥1,200,000（税別）**

# Part A — Customer-facing One-page Content

## IT経営KAIZEN

### 経営が目指す未来を、ITで実現する。

会社が成長すると、ITも複雑になります。

社員、拠点、SaaS、端末、アカウント、ベンダーが増え、Securityや管理の重要性も高まる。一方で、システムを増やしても、情シスの仕事や社員の手間が減っていない企業もあります。

IT経営KAIZENは、ツールや人員を先に提案するサービスではありません。

> **未来から考える。事実で決める。ITで変える。**

### 1. FUTURE
経営者が1〜3年後に実現したい会社の姿を確認します。

### 2. FACT
現在のIT、運用、管理を事実とEvidenceで確認します。分からないことはUNKNOWNとして残します。

### 3. KAIZEN
「なくす・自動化する・標準化する・任せる・残す・整える」の6つの視点で、仕事とITを再設計します。

### 4. DECISION
何を変えるかを経営と決めます。誰が担うかはその後です。

### 5. ACT / CHANGE
自社、既存ベンダー、他ベンダー、atLIBなど最適なActorで実行し、本当に会社が良くなったかをFACTで確認します。

### 最初の一歩 — 無料IT経営診断

まず、現在地を断定するのではなく、

- どんな未来を実現したいか
- 今わかっていること
- まだ確認できていないこと
- ITで改善できる可能性
- 次に何を確認・判断すべきか

を整理します。

> **可能性で会社を変えない。事実を確認してから、何を変えるかを決める。**

必要な場合は、次のステップとして「IT経営KAIZEN 設計Assessment」でEvidenceに基づく現在地と次の一手を設計します。

# Part B — 30-minute First Meeting Talk Track

## 0–3 min — Positioning

目的：製品営業 / BPO営業ではないことを明確にする。

Talk candidate：

「今日は特定のツールやアウトソーシングを前提にお話しするのではなく、御社がこれからどんな会社を目指しているのか、その実現にITをどう使えるかというところから伺いたいと思っています。」

## 3–10 min — FUTURE

Ask：
- これから1〜3年で会社をどう良くしていきたいですか？
- 今、経営として特に優先しているテーマは何ですか？
- 成長、生産性、採用、Security、Governance、DXなどで大きな変化はありますか？
- その未来に対してITへ期待していることはありますか？

Do not：
- すぐSolutionへ飛ぶ
- 相手の言葉を勝手にKGI化する

## 10–18 min — CURRENT FACT / UNKNOWN

Ask：
- 現在、ITを担っているのはどなたですか？
- 社員 / 拠点 / グループ会社はどの程度ですか？
- Microsoft 365 / Google Workspace / Identity等の基盤は？
- 端末 / Account / SaaSはどう管理していますか？
- 主なVendorは何社くらいですか？
- 経営は現在のITの状態をどう把握していますか？

Operator rule：
- Evidence未確認はFACTにしない
- 分からない回答はUNKNOWNとして記録

## 18–24 min — WORK / GAP

Ask：
- IT担当者は何に時間を使っていますか？
- 問い合わせ、入退社、Account、Device、Vendor調整などで負荷の高いものは？
- 同じ情報を複数のExcelやシステムへ更新している業務はありますか？
- システムを導入したのに仕事が減っていない例はありますか？
- IT担当者が本来やりたいが手を付けられていない仕事は？

Bridge：

「ここまでのお話だけでも改善できる可能性はいくつかありそうですが、まだEvidenceを確認していないので、現時点では可能性として扱うのがよいと思います。」

## 24–28 min — Free Diagnosis

Explain：

「まず無料IT経営診断で、目指す未来、分かっている事実、まだ分からないこと、Gap、次に確認すべきことを整理できます。ここでは無理にSolutionや当社への発注を結論にしません。」

## 28–30 min — Next Action

Close candidate：

「よろしければ一度、経営の目指す未来を起点に無料診断を実施して、ITでどこを良くできそうか整理してみませんか。」

# Part C — Free Diagnosis Invitation

## Verbal / Meeting

「ITの課題を並べる診断ではなく、まず会社が目指す未来を確認し、その未来に対して今のITがどうなっているかを整理する無料診断です。分からないことは分からないまま残し、次に何を確認すべきかまでお返しします。」

## Key Promise

- Sales pitch firstではない
- maturity scoreを付けるものではない
- unknownを断定しない
- 既存Vendor入替を前提にしない
- 次の経営判断を整理する

---

# Part D — Management Feedback Structure

無料診断後のFeedbackは以下の5枚 / 5ブロックで統一する。

## 1. FUTURE
「御社が実現したい未来」

## 2. FACT / UNKNOWN
「今わかっていること / まだ確認が必要なこと」

## 3. GAP
「未来に対して、現在どこにGapがありそうか」

## 4. WHY
「考えられるRoot Cause / 確認すべき原因」

HYPOTHESISをFACT化しない。

## 5. NEXT DECISION
「次に経営として何を確認・判断すべきか」

Assessmentが必要ならここで初めて提案する。

- Required IT Capability

# Part H — Objection Handling

## 「今のVendorがいる」

「入替を前提にしていません。まず今のITが経営の未来につながっているかをFACTで確認します。既存Vendorが最適なActorなら、そのまま活かすことも選択肢です。」

## 「診断なら無料でやってくれる会社もある」

「無料診断は当社にもあります。無料では改善可能性と次に確認すべきことまでを整理します。設計AssessmentはEvidenceを確認して、経営が実際に投資・実行Decisionできる現在地と改善設計を作る工程として分けています。」

## 「120万円は高い」

Do not immediately discount.

Ask：
- 何と比較して高いと感じるか
- 今回必要なDecisionは何か
- 誤った投資 / 採用 / Vendor選択の影響
- Scopeが過大でないか

Explain value, not hours.

## 「とりあえず運用だけお願いしたい」

「Scopeが明確でEvidenceも十分なら直接ご相談できる場合もあります。ただ、今の仕事をそのまま外へ移すだけでよいのか、なくせる仕事や自動化できる仕事がないかは確認した方が、結果的に合理的になる可能性があります。」

## 「何人来てくれるの？」

「人員数を提供単位にはしていません。必要なIT CapabilityとService Scopeを設計し、Operator、Engineer、Specialist等を必要に応じて組み合わせる考え方です。個別案件ではAssessment後にScopeと体制を提示します。」
