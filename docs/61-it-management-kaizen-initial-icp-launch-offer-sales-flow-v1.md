## 3. Initial ICP — Company Profile Hypothesis

初期ICPを社員数だけで定義しない。

### Primary ICP Hypothesis

> **ITの複雑性と投資規模は大きくなっているが、必要なIT Capabilityをすべて社内専門人材で持つには規模が足りず、既存の情シス運用にも改善余地がある中小・中堅企業。**

Employee ScaleのCandidate Zone：

> **100〜500名程度 — HYPOTHESIS, NOT DECISION**

特に検証優先候補は200〜400名前後。

理由は「人数そのもの」ではなく、以下が同時に起きやすいかを検証するため。

- SaaS / Device / Accountが増える
- 部門 / 拠点 / Vendorが増える
- Approval / Authorityが複雑化する
- Security / Governance要求が上がる
- Generalist一人ではCapability Coverageが難しくなる
- 一方、各専門CapabilityをFTEで内製するには重い
- Recurring Workが十分ありStandardization / FACTACT Leverageが効く可能性がある

## 4. Trigger-based ICP

営業では「社員300名」を狙うより、以下のTriggerを持つ企業を優先する。

### A. Organization Trigger

- 一人情シス / 少人数情シスが限界
- 情シス責任者の退職 / 交代
- 総務・人事兼任から専任化を検討
- IT人材を採用したいが採れない
- 外注先が増え、誰も全体を見ていない

### B. Growth / Change Trigger

- 100名→200名等の急成長
- 多拠点化
- グループ会社増加
- IPO準備
- M&A / 統合
- 新システム / SaaS増加

### C. Technology Trigger

- オンプレAD脱却
- M365 / Google Workspace再設計
- SSO / ID統合
- MDM / EDR
- Network刷新
- Cloud移行
- SaaS整理
- AI / DX活用

### D. Governance / Risk Trigger

- ISMS / ISO27001
- 監査
- Security事故 / ヒヤリハット
- 退職者Account管理不安
- IT資産 / Licenseが見えない
- Vendor任せで経営がITを把握できない

### E. Work Trigger

- 問い合わせに追われる
- 入退社対応が重い
- 同じ情報を複数台帳へ転記
- Excel管理が増え続ける
- Vendor間調整が情シスに集中
- 月次報告のために別作業が発生
- 「システムを入れたのに仕事が減っていない」

## 5. Strong-fit vs Weak-fit

### Strong-fit Candidate

- 経営者が会社のFuture / 成長課題を持っている
- ITを単なるコスト削減ではなく経営改善に使いたい
- IT環境が複雑化している
- 現在のIT運用に属人化 / 二重管理 / 分断がある
- Security / Governance / Continuityの重要性が上がっている
- 既存Vendorを必ずしも全交換したいわけではない
- Standardization / Connectionを受け入れられる
- FACTを確認してから投資Decisionする考えに共感する

### Weak-fit Candidate

- 「とにかく一人常駐してほしい」だけ
- 最安Helpdeskだけを求める
- 専任個人への直接指示を前提とする
- 物理オンサイト作業が大半
- IT投資・改善意思がほぼない
- Assessmentなしに固定価格だけを要求
- 既存運用を一切変えず、そのまま外注したい

Weak-fitでもFocused Projectが成立する可能性はある。会社全体を排除するのではなく、Managed CapabilityとのFitを分けて判断する。

## 7. Initial Launch Offer Architecture

Launch時点では商品を増やしすぎない。

### Offer 1 — 無料IT経営診断

Price：無料

Purpose：
> **ITで会社を良くできる可能性と、次に確認すべきことを見つける。**

Output：
1. FUTURE
2. Known / UNKNOWN
3. GAP
4. Why / possible root cause
5. Next Decisions

Do not：
- 成熟度Scoreを断定
- Evidence未確認事項をFACT化
- Detailed Solution Design
- Vendor選定
- atLIB発注を結論化

CTA：
> **可能性で会社を変えない。事実を確認してから、何を変えるかを決める。**

→ 設計Assessment

### Offer 2 — IT経営KAIZEN 設計Assessment

Price：**¥1,200,000 pre-tax — DECIDED**

Customer Arrival：
> **経営者が、事実をもとにIT経営の次の一手を決められる。**

Core Outputs：
- FUTURE / expected CHANGE
- FACT / UNKNOWN / Evidence
- GAP / ROOT CAUSE
- Required IT Capability
- KAIZEN Options
- Human Decision
- 1-year KGI / KPI
- Actor Allocation
- Commercial Decision input where atLIB execution is considered

AssessmentはatLIB Managed Serviceを売るための有料診断ではない。

### Offer 3 — KAIZEN Project

Price：Scope-based quote

Purpose：
> **DecisionしたCHANGEを実現する。**

Examples：
- Identity / SSO redesign
- 脱AD
- M365 / SaaS governance
- Device / MDM / EDR
- Network redesign
- Security / ISMS infrastructure improvement
- Workflow redesign / automation
- IT management process redesign

ProjectはAssessmentで選択されたACTの一つ。

### Offer 4 — Managed Capability

Price：Assessment / Commercial Quote EngineによるScope-based range

Purpose：
> **atLIBがActorとして選ばれたIT Capabilityを、Shared Capability + FACTACTで継続提供する。**

Not：
- 人月販売
- 単純な作業移管
- 固定BPOパッケージ

Value：
- 必要Capabilityを必要時に利用
- Human dependency圧縮
- Knowledge continuity
- Management visibility
- Continuous KAIZEN
- CHANGE / NEW FACT verification

Managed Capabilityが選ばれないAssessment結果も正常なOutcomeとする。

## 9. Sales Opening Question

初回商談を「情シスで困っていることは？」から始めない。

Candidate opening：

> **「これから1〜3年で、会社をどう良くしていきたいですか？」**

Then：

> **「その未来を実現するうえで、ITがもっとできることは何だと思いますか？」**

> **「今のIT運用や仕組みは、その未来に追いついていますか？」**

ここからFACT / UNKNOWNを分ける。

## 10. Sales Discovery — Minimum Questions

無料診断 / 初回商談で全Assessmentをしない。

最低限：

### FUTURE
- 1〜3年で会社をどうしたいか
- 成長 / 生産性 / Security / Governance / DX等の優先テーマ

### Current Structure
- Employees / locations / group companies
- IT staffing
- major vendors
- major platform / cloud / identity

### Trigger
- 今なぜITを見直したいのか
- 何が変わった / 変わるのか

### Work / Pain
- 何にHuman Workが使われているか
- 同じ情報を何度入力 / 管理しているか
- 問い合わせ / 入退社 / Account / Device / Vendor調整等

### Management
- IT投資を誰が決めるか
- 経営がITの状態をどう把握しているか
- Security / Audit / Risk要求

### UNKNOWN
- その場で分からないことを明示する

## 11. Qualification — Assessment Fit

Assessmentを提案するCandidate Signal：

- FUTUREとCurrent ITのGapがありそう
- 複数テーマが絡み単一製品導入では解けない
- Evidenceが不足している
- Actor / Vendor / Internal責任が曖昧
- IT投資Decisionに経営判断が必要
- Security / Governance / Growth impactがある
- Workそのものを再設計する余地がある

Assessmentを急がないSignal：

- 課題とSolutionが明確な単純Project
- 極小Scopeの作業依頼
- Evidenceが十分でDecision済み
- 経営改善ではなく単純調達のみ

Commercial Neutralityのため「全案件Assessment必須」とはしない。

## 12. Managed Capability Qualification

Assessment後にのみ精度を上げる。

Candidate Fit：
- recurring Workが十分ある
- Standardization可能
- FACT / Evidence connection可能
- Shared CapabilityがFTEより合理的
- Specialist needs are intermittent
- synchronous L1比率が過度に高くない
- onsite dependencyが過度に高くない
- customer accepts service-based Actor boundary
- FACTACT leverageが見込める

Output：
- atLIB Managed Scope
- Commercial Classification
- expected FACTACT leverage — HYPOTHESIS until measured
- Role Mix
- Delivery COGS
- Customer Alternative TCO
- Commercial Price Range

## 13. Launch Messaging

### Core Message — PROPOSAL

> **経営が目指す未来を、ITで実現する。**

Supporting：

> **未来から考える。事実で決める。ITで変える。**

### Differentiation

従来：
> ツールを入れる / 人を増やす / 作業を外へ出す

IT経営KAIZEN：
> FUTUREから必要なIT Capabilityを考え、FACTで現在地を確認し、仕事そのものをKAIZENして、最適なActorで実行する。

### Vendor-neutral Message

> **今のベンダーを変える必要はありません。まず、今のITが経営の未来につながっているかを事実で見ます。**

### Work-elimination Message

> **ツールは増えた。でも、仕事は減りましたか？**

> **管理表更新を外注するのではなく、管理表更新という仕事そのものを減らす。**

## 14. What Sales Must NOT Say

- 「300名なら80万円です」
- 「FACTACTで必ず50%工数削減できます」
- 「今のVendorは不要です」
- 「Assessmentを受ければatLIB運用になります」
- 「情シスを全部代行します」
- 「AIが最適解を決めます」
- 「無料診断で現在地を確定できます」
- 「成熟度○点です」 without defined/evidenced method
- 「3人月200万円相当を80万円で提供できます」 as a general guarantee

3人月比較は個別Customer Alternative TCOのEvidenceがある場合にのみ比較する。

## 17. First Target Account Strategy — PROPOSAL

Launch初期はCold Mass Marketingより、既存接点からFACTを集めることを優先する。

Priority candidate：

1. 既存顧客でIT体制 / 課題をある程度知っている企業
2. 100〜500名で経営者 / 管理役員へ接触可能な企業
3. 情シス責任者交代 / IPO / Security / M365 / 脱AD等のTriggerがある企業
4. 現在atLIBが人材 / キッティング等で一部関与し、全体ITはまだ見えていない企業
5. Existing Vendorを残したまま改善できる企業

目的：売上だけでなく、Assessment → Commercial Model → FACTACT leverageの実Evidenceを早く得る。
