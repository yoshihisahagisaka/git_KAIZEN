## 1. Price Governance — DECIDED

IT経営KAIZEN 設計Assessmentの標準価格は **1,200,000円（税別）** とする。

価格は原価から逆算して決めるのではなく、商品としての標準価値を基準に設定する。原価・提供工数・粗利は、1,200,000円の商品として事業が成立するかを検証するために管理する。

### 値引き権限

- 標準価格：1,200,000円（税別）
- 営業裁量：1,000,000円〜1,190,000円（税別）
- 800,000円〜990,000円（税別）：上長承認
- 800,000円未満：原則不可。例外は経営承認

### 値引き運用原則

- 値引き理由を記録する。
- 下限価格を標準提示価格として扱わない。原則として1,200,000円から提案する。
- 値引きを理由にAssessmentの方法論や成果物品質を下げない。
- 調査・分析の対象範囲を変更する場合は、単純な値引きではなくScope変更として扱う。
- 値引き実績・受注/失注結果をFACTとして蓄積し、将来の価格検証に使う。

## 2. Internal / Sales Language Principle — MANDATORY CANONICAL RULE

商品定義は、内部の方法論用語をそのまま営業・社内説明へ持ち込まない。

> **内部では厳密に管理する。営業・社内には、理解し説明できる言葉へ翻訳する。**

### Mandatory Rule

> **FACTACT・開発・設計側では厳密な内部用語を使用してよい。しかし、営業担当者や一般の社内メンバーが FUTURE / FACT / UNKNOWN / GAP / ROOT CAUSE / ACT Options / Actor 等の内部用語を覚えなければ、IT経営KAIZENを理解・説明・販売できない状態にしてはならない。**

この原則は推奨ではなく、IT経営KAIZENの商品定義、営業資料、営業教育、見積・提案、顧客説明を作成する際の標準ルールとする。

営業・社内向け資料のレビュー時には、以下を確認する。

1. 内部用語を知らない営業担当者が読んでも意味が分かるか。
2. その資料だけで顧客へ説明できるか。
3. 英語を日本語へ機械的に置き換えただけではなく、業務上の意味が伝わる表現になっているか。
4. 内部用語を削ったことで方法論の意味が変わっていないか。
5. 顧客へそのまま転送されても大きな誤解が生じないか。

### 主な翻訳例

- FUTURE → 経営者が実現したい会社の姿 / 会社の未来像
- FACT → 確認できた事実 / 現在の状況
- UNKNOWN → まだ分かっていないこと / 未確認事項
- GAP → 目指す姿と現在の差
- ROOT CAUSE → 差が生まれている主な原因
- ACT Options → 改善の選択肢
- Management Priority → 経営上の優先事項
- Scenario Comparison → 優先することによる改善案の比較
- Multi-year Roadmap → 数年先を見据えた改善の道筋
- Human Decision → 経営者が決める / 経営判断
- Actor → 実行担当 / 誰が実行するか
- Evidence → 確認の根拠 / 資料・記録・設定等
- CHANGE → 実際に何が変わったか
- Verification → 実際に変わったか確認する

## 3. Internal Sales Product Definition — DECIDED DIRECTION

### 商品名

**IT経営KAIZEN 設計Assessment**

※ Assessmentは商品名として残す。本文では必要に応じて「調査・分析」「今回の調査」等の日本語を使用する。

### この商品は何か

> **経営者が実現したい会社の姿から逆算して現在のITや業務を確認し、何を改善するかを経営判断できる状態をつくるコンサルティングサービス。**

### 何をするのか

1. 経営者が実現したい会社の姿と、経営上の優先事項を確認する。
2. 資料・記録・システム設定・ヒアリング等から、現在の状況を確認する。
3. 確認できたことと、まだ分かっていないことを分ける。
4. 目指す姿と現在の差、その主な原因を整理する。
5. 技術・運用・管理の視点から、複数の改善方法を考える。
6. 何を優先するかによって改善案を比較し、数年先を見据えた改善の道筋をつくる。
7. 経営者へ説明し、次に何を実行するかを決められる状態にする。

### お客様が受け取るもの

正式成果物の標準は既存Canonicalに従い、社内・営業向けには以下の3つで説明する。

1. **IT経営KAIZEN 改善計画書** — 調査・分析結果と改善案をまとめた詳細資料
2. **経営判断用の要約資料** — 経営者が重要な論点と選択肢を確認するための資料
3. **調査・分析資料** — 判断の根拠となった確認内容・記録

### この商品で決めること

> **会社を良くするために、次に何を改善するか。**

### この商品に含まれないこと

システム導入、設定変更、開発、継続運用等の実行そのものは、設計Assessmentとは分けて考える。

改善内容を決めた後、誰が実行するかは顧客が選ぶ。自社、既存ベンダー、atLIB、他社、複数者の組み合わせ等があり得る。

## 4. Sales Explanation — INTERNAL STANDARD

営業は、内部用語を並べて説明するのではなく、原則として次の順で説明する。

> **まず、経営者がこれからどんな会社にしたいのかを確認します。次に、現在のITや業務が実際にどうなっているのかを、資料や記録、システム設定、ヒアリングなどから確認します。そこから、目指す姿との違いと原因を整理し、複数の改善方法をつくります。最後に、経営者が選択肢を比較して「次に何をするか」を判断できるところまでご支援するのが、IT経営KAIZEN 設計Assessmentです。**

価格説明では工数売りに戻さない。

> **標準価格は120万円（税別）です。調査時間や報告書のページ数を販売するのではなく、会社の未来像と現在の状況を整理し、複数の改善方法と今後の道筋をつくり、経営者が次に何をするかを判断できるところまでを一つの商品として提供します。**

## 5. Guardrails

- 社内営業資料で英語・内部用語を多用しない。
- FUTURE / FACT / UNKNOWN / GAP / ROOT CAUSE / ACT Options / Actor 等の用語を営業担当者へ暗記させることを商品理解・説明・販売の前提にしない。
- 内部用語を日本語に置き換えただけで意味を変えない。
- 「全部調べるIT監査」と説明しない。
- 「必ず成果が出る」「必ず仕事が減る」等、未確認の成果を約束しない。
- Assessment後にatLIBへ実行を発注することを前提にしない。
- 値引きとScope変更を混同しない。
