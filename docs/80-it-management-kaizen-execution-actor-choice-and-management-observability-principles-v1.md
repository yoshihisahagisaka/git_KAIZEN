# IT経営KAIZEN — 実行者選択・atLIB実行支援・経営観測原則 v1

Status: CANONICAL — BUSINESS / EXECUTION SUPPORT
Date: 2026-09-16

## 1. Purpose

IT経営KAIZENにおける「何を改善するか」と「誰が実行するか」の境界、atLIBを実行者として選んだ場合の支援方法、実行後のActor選択、および経営者が実行者を選ぶ際に持つべき視点を定義する。

## 2. Core Decision

### 2.1 何を改善するかと、誰が実行するかを分ける

- まず、会社の未来像と確認できた現状をもとに「何を改善するか」を経営判断する。
- その後に、改善内容・社内体制・必要な専門性等を踏まえて実行方法・実行担当を選ぶ。
- 実行担当は、自社、既存ベンダー、atLIB、複数者の組み合わせ等から顧客が選択する。
- 実行者ありきで改善内容を決めない。

### 2.2 atLIBを選んだ場合の実行支援

atLIBが実行を支援する場合は、単なる作業代行を目的とせず、以下の流れで実行する。

1. 調査で確認した事実、まだ分かっていないこと、改善を決めた理由を実行へ引き継ぐ。
2. 安全・権限・影響範囲等、実行前に必要な確認を行う。
3. 実際の運用から件数・内容・時間・例外・手戻り等の実態を把握する。
4. 不要・重複・手戻りを見直し、標準化・自動化等によって仕事そのものを減らすことを検討・実行する。
5. 実際に何が変わったかを確認し、次の改善判断につなげる。

顧客向けの要約表現：

> 仕事を任せる → 実態を知る → 仕事を減らす → 仕組みにする

これはatLIBを実行者として選んだ場合の提供方法であり、IT経営KAIZENのActor Neutralityを否定するものではない。

### 2.3 atLIB継続を前提にしない

- atLIBによる実行支援を開始した後も、atLIB継続を前提としない。
- 改善後の業務・体制・システム・コスト等を確認し、その時点で会社に合った運用方法を顧客が検討する。
- 選択肢には、自社運用、SaaS・自動化、atLIB継続、他社への引継ぎ、複数方法の組み合わせ等があり得る。
- 実際に選択可能な方法は、改善内容およびその時点の状況によって異なる。すべての選択肢へ必ず移行できるとは約束しない。

## 3. Management Advisory — 実行者を選ぶ際の経営視点

IT経営KAIZENは、実行者の選択を顧客に委ねるだけで終わらない。誰を実行者として選ぶ場合でも、経営者が以下の視点を持って判断できるよう支援する。

### 3.1 会社の未来像から逆算する

目の前の困りごとだけでなく、これからどのような会社にしたいのか、そのためにITをどう使うのかから考える。

### 3.2 専門家に丸投げしない

経営者が技術の細部まで理解する必要はない。一方で、「何をするのか」「なぜ必要なのか」「何が変わったのか」は経営者が理解できる形にする。

### 3.3 確認できる根拠を求める

「対応しています」「問題ありません」といった説明だけでなく、件数・時間・状態・記録等、経営者にも確認できる形で示される状態を目指す。

### 3.4 会社に知識が残るようにする

特定の担当者・専門家しか分からない状態を避け、手順・判断理由・必要な記録等が会社側にも残るようにする。

### 3.5 実行後の変化まで確認する

システム導入や外注開始をゴールにせず、仕事・社員・リスク等が実際にどう変わったかを確認する。

## 4. Customer-facing Principle

> 専門家に任せることと、経営を任せることは違います。
>
> 専門的なITを、経営者が理解し、確認し、判断できる形にする。そこまでがIT経営KAIZENのコンサルティングです。

この表現は、「内部では厳密に管理し、顧客には判断できる言葉へ翻訳する」という既存のCustomer Language Principleに従う。

## 5. Relationship to Existing Canonical

- Assessmentは「何をするか」を決める商品であり、実行支援は「どう実現するか」の選択肢の一つである。
- Actor Neutralityを維持する。
- Human Decisionの対象は、実行するACTおよびActor選択であり、atLIBが自動的にActorになるわけではない。
- atLIBを選択した場合には、Assessmentで確認した内容を実行へ連続させる価値を提供する。
- CHANGEは実行後に確認する対象であり、実行前に成果を断定しない。

## 6. Supersession / Guardrails

以下の解釈へ戻してはならない。

- Assessment受注後はatLIBが当然に実行者になる。
- atLIBを使い続けることがIT経営KAIZENのゴールである。
- KAIZENを開始すれば仕事が自然に仕組み化される。
- すべてのUNKNOWNを解消しなければ実行を開始できない。
- 専門家へ委託した時点で経営者はITを観測・判断しなくてよい。

## 7. Customer-facing Collateral Structure

実行支援説明資料は、以下の4ページ構成を標準ストーリーとする。

1. 誰が実行するかは、お客様が選べます。
2. atLIBを選んだ場合は、こう実行します。
3. その後の運用方法も、お客様が選べます。
4. 実行者を選ぶとき、経営者に持ってほしい視点があります。

この構成により、Actor Neutrality、atLIBの提供価値、Exit Option、経営コンサルティング価値を混同せずに説明する。
